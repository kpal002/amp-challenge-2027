# Submission checklist

Deadline: **2026-09-30, 15:00 PDT**. Everything on the engineering side is done
and verified; the items below need account access and so cannot be automated.

## 1. Join the hackathon

Submission is a Kaggle **Writeup**, not a file upload. On
<https://www.kaggle.com/competitions/amp-challenge>: press **Join Hackathon**,
then **Writeups → New Writeup**.

Eligibility per the Kaggle rules is only: a registered Kaggle account, 18+, and
not resident in a sanctioned jurisdiction. There is **no institutional-email
requirement** on the Kaggle rules page, the competition overview, or the official
website.

## 2. Submit ONE library, not five

The five competition categories are **award categories applied to the same
peptides**, not five separate submissions. From the competition overview: "Every
peptide is evaluated against all strains and for hemolysis (HC50) regardless of
category, and awards are given in these five categories."

The Kaggle rules are explicit that multiple entries are not allowed for one
model: "Each team may submit peptides generated by a given model only once. If a
team has two or more sufficiently different models, it may submit one entry per
model." Our five category entry points share one set of weights and differ only
by a control token, so they are one model and warrant **one entry**.

Submit `generate/` (the broad-spectrum output). It is also the strongest on the
independent seqme evaluation — top-100 FBD 3.94 and recall 0.86, against 7.33 /
0.62 for `therapeutic` — and the 25 assayed peptides are scored in all five award
categories regardless.

The other four entry points remain in the repository as documented alternatives;
they are not part of the submission.

## 3. Push the repository

The work is committed locally on `main` as a single initial commit. Create an
empty GitHub repository, then:

```bash
cd ~/amp-challenge
git remote add origin git@github.com:<your-user>/<your-repo>.git
git push -u origin main
```

Then in the repository's **Settings → Collaborators**, grant read access to
`@RasmusML` and `@szymczakpau`.

For co-authorship eligibility the repository must be **public** and carry a
permissive OSI licence — MIT is already in place as `LICENSE`.

## 4. Verify what the organizers will verify

Already run and passing locally, but re-run after pushing so the check reflects
the pushed remote rather than the local tree:

```bash
cd /path/to/amp-challenge-2027-template
uv run python scripts/verify_submission.py https://github.com/<your-user>/<your-repo>
```

Expected final line: `All checks passed. Submission is valid!`
